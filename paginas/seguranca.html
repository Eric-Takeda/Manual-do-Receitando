Segurança do sistema

A segurança do Receitando envolve a proteção das contas, o controle de acesso aos dados e o gerenciamento dos arquivos armazenados.

O aplicativo utiliza os recursos de segurança do Supabase e as regras implementadas no Flutter para controlar as operações disponíveis aos usuários. A proteção efetiva depende da configuração correta desses recursos.

1. Autenticação de usuários

O Supabase Auth é utilizado para gerenciar o cadastro, o login e a sessão dos usuários.

A autenticação permite identificar a conta que está utilizando o aplicativo. Esse identificador pode ser utilizado nas regras de acesso aos dados.

  • Cadastro de contas;
  • Login com e-mail e senha;
  • Encerramento da sessão ao sair da conta;
  • Fluxo de recuperação de senha.

2. Controle de acesso ao banco de dados

O banco de dados utiliza políticas de acesso para determinar quais operações cada usuário autenticado pode realizar.

O Supabase oferece o recurso Row Level Security (RLS), que permite aplicar regras diretamente nas tabelas. Quando configurado corretamente, ele ajuda a impedir que um usuário consulte ou altere registros que não estão autorizados para sua conta.

As políticas devem considerar as tabelas utilizadas pelo aplicativo, como profiles, receitas, ingredientes e favoritos.

3. Proteção das receitas

O aplicativo deve diferenciar as receitas criadas pelos usuários daquelas disponibilizadas previamente pelo sistema.

A edição e a exclusão de receitas próprias devem ser permitidas somente quando o usuário tiver autorização para realizar essas operações.

As receitas previamente disponibilizadas pelo sistema devem permanecer protegidas contra alterações ou exclusões realizadas por usuários comuns.

Além de ocultar ou desabilitar botões na interface, é importante configurar as políticas de banco de dados para impedir operações não autorizadas diretamente pela API.

4. Proteção dos favoritos

Os favoritos são associados ao identificador do usuário autenticado. Assim, cada conta deve conseguir consultar e administrar apenas os registros que lhe pertencem.

A tabela favoritos utiliza os campos user_id e receita_id para relacionar o usuário à receita favoritada.

5. Segurança das imagens

O Supabase Storage armazena as imagens das receitas e as fotos de perfil nos seguintes buckets:

  • recipe-images — imagens de receitas;
  • profile-images — fotos de perfil.

As políticas de armazenamento devem controlar quem pode enviar, substituir ou excluir arquivos. Quando necessário, as regras podem limitar essas operações aos arquivos associados ao próprio usuário.

Mesmo quando um bucket permite a leitura pública de imagens, isso não significa que qualquer pessoa deva poder modificar ou excluir os arquivos. Leitura e alteração são permissões diferentes.

6. Proteção de credenciais

As credenciais utilizadas para conectar o aplicativo ao Supabase devem ser tratadas corretamente.

A chave pública destinada ao cliente pode ser utilizada no aplicativo quando as políticas de acesso estiverem configuradas adequadamente. Já a chave secreta ou a chave administrativa, como a antiga service_role, nunca deve ser incluída no código distribuído ao usuário.

Senhas pessoais também não devem ser armazenadas diretamente nas tabelas do aplicativo. O gerenciamento das senhas deve ser realizado pelo serviço de autenticação.

7. Validação dos dados

Os campos dos formulários devem ser validados antes de enviar os dados ao banco de dados.

Alguns exemplos de validação são:

  • Verificar se os campos obrigatórios foram preenchidos;
  • Validar se o tempo de preparo e as porções possuem valores adequados;
  • Evitar salvar receitas sem as informações necessárias;
  • Apresentar mensagens claras quando ocorrer um erro.

As validações feitas na interface devem ser complementadas por restrições e políticas no banco de dados sempre que necessário.

8. Encerramento da sessão

Ao selecionar a opção de sair, o aplicativo utiliza o método de encerramento de sessão do Supabase Auth. Isso evita que a conta continue autenticada naquela sessão do aplicativo.

Após o encerramento, a navegação deve retornar à tela de login, impedindo que o usuário continue utilizando as áreas restritas como se ainda estivesse autenticado.

9. Politicas

Políticas de segurança do banco de dados

O banco de dados utiliza políticas de segurança do Supabase, por meio do mecanismo Row Level Security (RLS), para controlar as operações que os usuários podem realizar nas tabelas. Cada política define permissões específicas de acordo com o usuário autenticado e a finalidade dos dados.

--------------------------------------------------------------------------------------------------------------------------------------------------------------------------

Tabela profiles

A tabela profiles possui três políticas: SELECT, que permite ao usuário visualizar seu próprio perfil; UPDATE, que permiteatualizar seus dados sem alterar sua associação com a conta; e INSERT, que permite criar um perfil vinculado ao próprio usuário. Essas regras utilizam auth.uid() = id para verificar a identidade do proprietário do perfil.

--------------------------------------------------------------------------------------------------------------------------------------------------------------------------

Tabela receitas

A tabela receitas possui políticas para as operações SELECT, INSERT, UPDATE e DELETE. Elas controlam, respectivamente, a visualização, a criação, a atualização e a exclusão das receitas, utilizando auth.uid() = user_id para associar as operações ao usuário responsável pelo registro.

--------------------------------------------------------------------------------------------------------------------------------------------------------------------------

Tabela ingredientes

A tabela ingredientespossui políticas para visualização (SELECT), criação (INSERT), atualização (UPDATE) e exclusão (DELETE). Essas regras permitem que o usuário gerencie os ingredientes das próprias receitas. Para verificar a permissão, o sistema consulta a tabela receitas e confirma se a receita relacionada ao ingrediente pertence ao usuário autenticado, utilizando o campo user_id.

--------------------------------------------------------------------------------------------------------------------------------------------------------------------------

Tabela categorias

A tabela categorias possui uma política de visualização (SELECT) que permite que usuários autenticados consultem as categorias cadastradas. Essa regra utiliza USING (true), permitindo a consulta sem restringir as categorias a um usuário específico.

--------------------------------------------------------------------------------------------------------------------------------------------------------------------------

Tabela receita_categorias

A tabela receita_categorias possui políticas para visualização (SELECT), inclusão (INSERT) e exclusão (DELETE) dos vínculos entre receitas e categorias. Essas regras verificam se a receita relacionada pertence ao usuário autenticado, impedindo que ele gerencie esses vínculos em receitas de outros usuários por meio dessas operações.

--------------------------------------------------------------------------------------------------------------------------------------------------------------------------

Tabela favoritos

A tabela favoritos possui políticas para visualização (SELECT), criação (INSERT) e exclusão (DELETE). Elas permitem que o usuário consulte, adicione e remova seus próprios favoritos. A condição auth.uid() = user_id garante que cada operação esteja associada ao usuário autenticado.

--------------------------------------------------------------------------------------------------------------------------------------------------------------------------

Armazenamento de imagens de perfis

No Supabase Storage, o bucket profile-images possui políticas para envio (INSERT), visualização, (SELECT), atualização (UPDATE) e exclusão (DELETE) de imagens de perfil. O envio verifica se a primeira pasta do caminho da imagem corresponde ao identificador do usuário autenticado. Já a atualização e a exclusão verificam a propriedade do arquivo por meio do campo owner_id, restringindo essas operações aos arquivos pertencentes ao usuário.

--------------------------------------------------------------------------------------------------------------------------------------------------------------------------

Armazenamento de imagens de receita

O bucket recipe-images possui políticas para envio (INSERT), visualização (SELECT), atualização (UPDATE) e exclusão (DELETE) das imagens das receitas. Assim como no armazenamento das fotos de perfil, o envio verifica o identificador do usuário na primeira pasta do caminho do arquivo, enquanto a atualização e a exclusão verificam o campo owner_id. Dessa forma, as operações de gerenciamento das imagens ficam restritas aos arquivos pertencentes ao usuário autenticado.

Considerações finais

A segurança do aplicativo depende da combinação entre autenticação, políticas de acesso, validação dos dados e gerenciamento adequado dos arquivos. Esses mecanismos devem ser testados para verificar se usuários sem autorização não conseguem consultar, modificar ou excluir informações protegidas.
